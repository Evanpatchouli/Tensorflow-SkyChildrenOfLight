## 记录事件和候选资格

- 先将可追溯来源加入 `sources`，用 `kind` 标记原档、社区整理和官方公告。先祖统一引用 `ancestors[].id`，沿用原档的 ID 和名称。
- 按完整档号顺序在 `events` 追加事件。每个档期一条，`ancestorIds` 可含多位先祖。活动与公告日期需要各自的来源依据，未知用 `null`。活动类型可区分普通旅行 `traveling`、集体回归 `group`、组合或特殊活动 `special` 与未知 `unknown`。如只核实了部分名单，设 `outcomeComplete: false`。缺少完整名单的期只计入已录档数。
- `eligibility.observations` 记录先祖 ID、服务器、平台、`status`、资格生效日 `effectiveFrom`、当时可知的公开日或时刻 `knownAt` 和官方 `sourceIds`。回放只能采用在截止前已经公开且生效的同平台记录。当前没有足以确认任何候选首次具备普通复刻资格的逐人证据。实际来访日期提供回归事实，尚无法确定其最早资格。
- 追加事件后重新生成榜单。历史读取新增的实绩，榜单从最新档号推演下一档，回测窗口随档案更新。原档快照中的复刻计数、手工热度、训练抽样和标签留在 `legacy/`。该目录及原模型权重只服务独立的 TensorFlow 实验。

## 生成和复现

从仓库根目录运行，所需输入均已纳入版本控制。

```powershell
node scripts/generate-prediction.mjs
node scripts/generate-prediction.mjs --check
node scripts/generate-prediction.mjs --period 83
node scripts/generate-prediction.mjs --report
node --test scripts/generate-prediction.test.mjs
```

生成器写入 [`prediction.json`](../src/assets/data/prediction.json)，其中包含算法版本、档案版本、截止档号和按 `JSON.stringify` 得到输入后计算的 SHA-256。档号相同而事实修订时，内容指纹仍可区分生成依据。单期报告可生成每位候选的等待档数、既往普通复刻次数、资格证据和真标签，也提供完整真实名单、池内名单和首次观测名单。全量报告分别提供按档号回放与有公告证据的回放。浏览器读取静态档案和排名。

## 回测

- 按档号回测使用第 41 至 83 档。每期只用更早的已收录档期建立特征和拟合经验模型。此窗口的样本包含社区索引核对的档期。
- 公告时点窗口使用第 79 至 83 档。每期截止到该期已核实公告发布日的前一天，只使用当时已开始且有活动日期的较早档期。截止依据是已核实的公告渠道。
- 两个普通旅行窗口均使用已出现先祖作为候选代理。公告时点另允许加入已核实资格的候选、排除已知不合格者。真实名单里未进入池的首次来访继续计入分母，完整候选池尚未覆盖。目前长窗口 43 期中有 28 个真实先祖位在池内，15 个是首次普通复刻。公告窗口 5 期中有 4 个在池内，1 个是首次普通复刻。
- 集体复刻使用单独窗口和同一普通复刻代理排序评估名单表现。当前档案尚无足以按此口径评分的集体回归期。集体档与组合装扮档均不改变普通复刻等待。
- Top 1、3、5 的期命中率以有完整真实名单的对应档期数为分母，任一真实先祖入榜即算该期命中。名单召回用排名覆盖的真实先祖位除以真实先祖位总数，完整命中需要命中整份名单。随机基线在同一候选池均匀无放回抽取，以数学期望汇总，因此命中数可为小数。
- 最长等待按自上次普通复刻起的已观测档数排序，同分按先祖 ID 排序。等待分桶经验模型以同一时点此前的已观测档拟合，然后用固定的 20 次机会权重向总体复刻率平滑。正式推演固定采用最长等待。
